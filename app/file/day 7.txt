1. [[pytest 基础]] — 让代码「可信」的最低门槛

它是什么： pytest 是 Python 最主流的测试框架。写测试就是写以 test_ 开头的函数，用 assert 断言结果符合预期。pytest 自动发现并运行这些函数，输出通过/失败的统计。

它解决 Agent 工程里的什么痛点： 你 Day 6 刚重构完 llm_client.py，怎么证明「没改坏」？靠手点一遍 CLI？太慢且不可复现。测试让「重构是否安全」有了可重复验证的标准——跑一遍 pytest，全绿就是没改坏。Week 7 的 AI-Interview 有 8 个模块，没有测试的话，改评分逻辑时根本不敢动其他模块。

今天为什么必须学： 本周核心产出物要求「至少 3 个测试用例」。今天给 config、history 写测试，学会测试的基本套路（构造输入 → 调用函数 → 断言输出），Week 2-8 每个项目都会用到。

新手最容易踩什么坑：
- 测试依赖真实外部服务（真的调 LLM API）——慢、花钱、不稳定。应该用 mock 隔离
- 测试之间有共享状态（都往同一个文件写），跑一次通过、跑第二次挂——要用临时目录隔离
- 只测 happy path（正常输入），不测边界和异常——真正的 bug 都藏在边界里

2. [[Mock 测试思路]] + [[项目复盘]] — 隔离依赖、沉淀价值

它是什么： Mock（模拟）是用假的实现替换真实的外部依赖——比如测试 LLMClient 时用 mock 的 httpx.Response 代替真实 API 响应，这样测试不需要网络、不花钱、跑得快。项目复盘是把本周「学了什么、踩了什么坑、产出了什么、能讲什么」结构化地总结成文字。

它解决 Agent 工程里的什么痛点： Agent 项目重度依赖外部 API（LLM、向量库、工具），如果测试都要真实调用，CI 跑一次要几分钟还花钱。Mock 让你把「我的逻辑对不对」和「外部服务是否正常」分开验证。复盘解决的是「学了一周，好像会了又好像没会」——把隐性经验变成显性可讲的内容，这是面试表达的唯一来源。


新手最容易踩什么坑：
- Mock 用错地方——mock 掉自己正在测试的代码，测试变成「测试 mock 本身」，毫无意义
- 复盘写成流水账「今天写了 xxx」——复盘要回答「为什么这么设计」「遇到什么问题怎么解决」「下次怎么改进」
