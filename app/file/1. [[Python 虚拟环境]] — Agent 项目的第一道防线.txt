

2. [[JSON 文件读写]] + [[环境变量与 API Key]] — 配置与持久化的地基

它是什么： json 模块把 Python 的 dict/list 序列化成字符串存到文件，读出来再反序列化回 Python 对象。python-dotenv 从 .env 文件读取键值对，注入到 os.environ。

它解决 Agent 工程里的什么痛点： LLM API Key 是付费凭证，硬编码在代码里 = 一行 git push 就可能泄露，被人盗刷。对话历史不持久化 = 每次重启程序丢失所有上下文，Agent 的多轮对话能力直接废掉。

今天为什么必须学： 今天写的 config.py 和 history.py 是整个 week1_llm_cli 项目的基础设施。后面 Day 3 调 LLM API 要用 Key，Day 5 交互式对话要靠 history 存上下文。

新手最容易踩什么坑：
- json.dump 写入中文变成 \uXXXX——加 ensure_ascii=False
- .env 文件里加引号：KEY="value" → 读出来带引号
- 文件路径硬编码 /home/user/data/ → 换台电脑就挂

def _find_env_file() -> Path | None:
    """向上查找 .env 文件，返回第一个存在的路径。

    查找顺序：
    1. 当前工作目录
    2. 当前文件所在目录向上两级（app/config.py -> week1_llm_cli/）

    返回 None 表示没找到 .env 文件。
    """
    # 先在当前工作目录找
    cwd_env = Path.cwd() / ".env"
    if cwd_env.exists():
        return cwd_env

    # 再在项目根目录找（假设 config.py 在 app/ 下）
    project_root = Path(__file__).resolve().parent.parent
    project_env = project_root / ".env"
    if project_env.exists():
        return project_env

    return None


def get_config() -> AppConfig:
    """读取 .env 配置并返回 AppConfig 实例。

    调用方不需要传任何参数——这个函数自动找到 .env 并解析。

    Raises:
        ConfigError: 缺少 .env 文件或必要配置项时抛出。
    """
    env_path = _find_env_file()
    if env_path is None:
        raise ConfigError(
            "找不到 .env 文件。\n"
            "请在项目根目录创建 .env 文件，参考 .env.example 的格式。\n"
            "最小 .env 内容：\n"
            "  LLM_API_KEY=your-api-key\n"
            "  LLM_BASE_URL=https://api.deepseek.com/v1\n"
            "  LLM_MODEL=d
    model = os.getenv("LLM_MODEL")

    # 逐一检查，给出精确的错误提示——不让用户猜哪个变量没配
    missing: list[str] = []
    if not api_key:
        missing.append("LLM_API_KEY")
    if not base_url:
        missing.append("LLM_BASE_URL")
    if not model:
        missing.append("LLM_MODEL")

    if missing:
        raise ConfigError(
            f"以下环境变量未配置：{', '.join(missing)}\n"
            f"请检查 .env 文件（路径：{env_path}）确保这些字段都已填写。"
        )

    return AppConfig(api_key=api_key, base_url=base_url, model=model)

你需要观察什么：
- _find_env_file() 为什么先查 Path.cwd() 再查相对路径：因为在不同目录执行 python main.py 时，当前工作目录可能不同
- get_config() 为什么返回 AppConfig 对象而不是 dict：dataclass 让你写 cfg.api_key 而不是 cfg["api_key"]，拼错 IDE 会标红
- __repr__ 为什么不直接打印 api_key：防止日志文件泄露密钥

"""
week1_llm_cli 程序入口 — Day 1 最小验证版本。

今天只验证两件事：
    1. 配置能正确读取（.env 解析正常）
    2. 历史记录能正确读写（JSON 持久化正常）

Day 3-5 会逐步加入 LLM 调用和交互式命令行。
"""

import sys
from pathlib import Path

# 把项目根目录加入 sys.path，确保在任意目录执行 python main.py 都能找到 app 包
PROJECT_ROOT = Path(__file__).resolve().parent
if str(PROJECT_ROOT) not in sys.path:
    sys.path.insert(0, str(PROJECT_ROOT))

from app.config import get_config, ConfigError
from app.history import save_message, load_messages, HistoryError

HISTORY_FILE = PROJECT_ROOT / "data" / "history.json"


def main() -> None:
    """Day 1 最小验证：配置读取 + 历史记录读写。"""
    print("=" * 50)
    print("  week1_llm_cl
    print("\n[1/2] 验证配置读取...")
    try:
        cfg = get_config()
        print(f"  ✅ 配置读取成功：{cfg}")
    except ConfigError as e:
        print(f"  ❌ 配置读取失败：\n{e}")
        print("\n  👉 解决方法：在项目根目录创建 .env 文件，内容如下：")
        print("    LLM_API_KEY=你的APIKey")
        print("    LLM_BASE_URL=https://api.deepseek.com/v1")

    # ---- 步骤 2：验证历史记录 ----
    print("\n[2/2] 验证历史记录读写...")
    try:
        # 保存一条测试消息
        save_message(HISTORY_FILE, "user", "[Day 1 测试] 这是一条验证消息")

        messages = load_messages(HISTORY_FILE)

            ts = msg.get("timestamp", "?")
            print(f"     [{i}] {role}: {content[:50]}{'...' if len(content) > 50 else ''} ({ts[:19]})")
    except HistoryError as e:
        print(f"  ❌ 历史记录操作失败：\n{e}")
        return

    # ---- 完成 ----
    print("\n" + "=" * 50)
    print("  ✅ Day 1 地基验证全部通过！")
    print("  👉 下一步：创建 .env.example 和 .gitignore")
    print("=" * 50)


if __name__ == "__main__":
    main()

📌 今日核心死磕

1. [[HTTP 请求结构]] — Agent 与外部世界对话的唯一语言

它是什么： HTTP 是客户端和是怎么传的、Body 里 messages 数组是什么格式、收到 429 该重试还是报错，明天写 LLMClient 就是照抄代码而不理解，出了错只能干瞪眼。

新手最容易踩什么坑：
- GET 请求把数据放在 Body 里（GET 不应该有 Body，参数放在 URL Query String 里）
- 把 Content-Type: application/json 写错成 text/plain，服务端解析不了
- 不看状态码，response.text 直接当成功结果用——可能是 HTML 错误页面

---

2. [[httpx 异步请求]] — 为什么 Agent 项目不直接用 requests

它是什么： httpx 是一个支持 HTTP/2 和异步的 Python HTTP 客户端库，API 设计和 requests 几乎一样，但多了一个 AsyncClient。

它解决 Agent 工程里的什么痛点： requests 是同步阻塞的——发一个请求，必须等它返回才能做下一件事。Agent 项目经常需要同时做多件事：调 LLM 生成回答 + 查向量数据库找相关文档 + 调外部 API 获取实时数据。用 requests 只能一件一件等（3 秒 + 2 秒 + 1 秒 = 6 秒），用 httpx.AsyncClient + asyncio.gather 可以同时发三个请求（总耗时 ≈ 最慢那个，约 3 秒）。

今天为什么必须学： Day 4 要做异步并发调用和耗时统计。今天先搞懂 httpx 的基本用法——同步 Client 怎么封装、怎么设 timeout、怎么处理异常——Day 4 切到 AsyncClient 就只是语法层面的变化，不会卡在 HTTP 概念上。

新手最容易踩什么坑：
- 忘记调 response.raise_for_status()——状态码 500 也不报错，后续代码拿 response.json() 解析出 HTML 报错页面然后崩掉
- timeout 设太大（等 60 秒）或太小（LLM 推理还没完就断了），不理解 connect timeout 和 read timeout 的区别

你需要观察什么

1. GET 和 POST 返回的状态码不同：GET 成功是 200，POST 创建成功是 201。这是 RESTful 惯例——201 Created 明确告诉你"资源创建了"。
2. httpbin 场景里服务端返回的 Headers：注意 Content-Type: application/json 是 httpx 自动帮你加的，不需要手动设。但如果传 data= 而不是 json=，它就不会加这个头——服务端可能解析失败。
3. 错误场景 A 的表现：404 Not Found → 抛出了 HTTPStatusError 而不是 NetworkError。这说明请求成功到达了服务端，只是资源不存在——这和断网是完全不同的问题，需要的处理策略也不同（404 没必要重试，网络错误可以重试）。

📌 今日核心死磕

1. [[OpenAI-compatible API]] — 所有 LLM 调用的通用语言

它是什么： OpenAI-compatible API 是一种事实标准——绝大多数国产大模型（DeepSeek、Qwen、GLM、Moonshot）都提供与之兼容的接口格式。核心是 /v1/chat/completions 端点，通过 messages 数组发送对话，返回 choices[0].message.content。

它解决 Agent 工程里的什么痛点： 你不可能只用一个模型。今天用 DeepSeek 便宜量大，下周某个任务需要更好的指令遵循能力就切到 Claude，下个月公司统一采购了某个国产模型。如果每个模型都要重写调用代码，Agent 项目就变成了适配器地狱。OpenAI-compatible 格式让你换模型只改 URL 和 API Key，不改代码。

今天为什么必须学： Day 5 要交付一个完整的 LLM CLI 工具。如果今天不把 LLMClient 封装好——包括消息构建、角色管理、错误处理——Day 5 的交互式 CLI 就没法调用任何模型，项目核心功能缺失。

新手最容易踩什么坑：
- Authorization 头写 Authorization: sk-xxx 而不是 Authorization: Bearer sk-xxx，返回 401 一脸懵
- messages 里 role 拼成 "role": "system" 能跑，拼成 "role": "sys" 不报错但模型不听你的系统指令
- 不检查 finish_reason——模型可能因为 token 不够截断了回答，你却当完整回答用

---

2. [[LLM messages 结构]] — Agent 记忆的底层数据结构

它是什么： messages 是一个数组，每个元素是 {"role": "角色", "content": "内容"}。三种核心角色：
- system：设定 AI 的行为边界和能力（"你是一个严谨的 Python 后端面试官..."）
- user：用户的问题或指令
- assistant：模型的回答

它解决 Agent 工程里的什么痛点： Agent 的多轮对话、上下文管理、Function Calling 的工具调用历史，全部依赖 messages 数组。Agent 的"记忆"本质上就是把过去所有轮次的 user/assistant/tool 消息不断追加到这个数组里，每次请求原样带上。

今天为什么必须学： 今天写的 LLMClient.chat_with_history() 方法要构建 messages 数组。如果搞不清楚 system prompt 放哪里、历史消息怎么拼、user prompt 是不是每次都要重复所有历史——Day 6-7 的 ReAct Agent 就直接没法学。

新手最容易踩什么坑：
- 每次都把 system prompt 当 user 消息发——模型会认为系统指令是"上一轮的对话内容"，遵守力度大降
- history 不断累加不设上限 → 第 20 轮对话时 messages 可能有 20KB，token 消耗暴涨且模型开始遗忘早期指令

        """单轮对话：发一个 user prompt，返回模型回答文本。

        如果有 system 参数，会自动构建 system + user 两条消息。
        如果没有 system，只发一条 user 消息（模型用默认行为）。

        Args:
            prompt: 用户输入的问题或指令。
            system: 可选的系统提示词，用于设定 AI 的角色。
            temperature: 0-2，越低越确定，越高越有创造性。
            max_tokens: 最大输出 token 数。

        Returns:
            模型回答的纯文本内容。

        Raises:
            AuthenticationError: API Key 错误
            RateLimitError: 请求频率过高
            ModelError: 模型不存在
            NetworkError: 网络不通
            TimeoutError: 响应超时
        """
        messages: list[dict[str, str]] = []
        if system:
            messages.append({"role": "system", "content": system})
        messages.append({"role": "user", "content": prompt})

        return self.chat_with_history(messages, temperature=temperature, max_tokens=max_tokens)

    def chat_with_history(
        self,
        messages: list[dict[str, str]],
        *,
        temperature: float =
        max_tokens: int = 2048,
    ) -> str:
        """多轮对话：传入完整的 messages 历史，返回模型回答。

        messages 格式必须是 [{"role": "...", "content": "..."}, ...]。
        role 必须是 "system"、"user" 或 "assistant" 之一。

        Args:
            messages: 完整的消息列表，包括 system/user/assistant 所有历史。
            temperature: 0-2，越低越确定。
            max_tokens: 最大输出 token 数。

        Returns:
            模型回答的纯文本内容。

        Raises:
            ValueError: messages 格式不正确
            AuthenticationError: 认证失败
            RateLimitError: 速率限制
            ModelError: 模型不存在
            NetworkError: 网络不通
            TimeoutError: 超时
            LLMError: 其他 LLM API 错误
        """
        # ---- 参数校验 ----
        self._validate_messages(messages)

        # ---- 构建请求 ----
        url = f"{self._base_url}{self.CHAT_ENDPOINT}"
        headers = {
            "Authorization": f"Bearer {self._api_key}",
            "Content-Type": "application/json",
        }
        payload = {
            "model": self._model,
            "messages": messages,
            "temperature": temperature,
            "max_tokens": max_tokens,
        }

        # ---- 发送请求 ----
        try:
            response = self._client.post(url, headers=headers, json=payload)
        except httpx.ConnectError as e:
            raise NetworkError(
                f"无法连接到 LLM API: {self._base_url}\n"
                f"检查: 1) 网
            ) from e
        except httpx.ReadTimeout as e:
            raise TimeoutError(
                f"LLM API 响应超时（90 秒）: {self._base_url}\n"
                f"可能原因: 模型推理慢、prompt 太长、服务端负载高\n"
                f"建议: 缩短 prompt 或换更快的模型"
            ) from e
        except httpx.RequestError as e:
            raise NetworkError(f"LLM API 请求失败: {e}") from e

        # ---- 处理错误状态码 ----
        self._handle_error_status(response)

        # ---- 解析响应 ----
        return self._parse_response(response)

    # ----------------------------------------------------------
    # 内部方法
    # ----------------------------------------------------------

    def _validate_messages(self, messages: list[dict[str, str]]) -> None:
        """校验 messages 格式。

        不在这里做复杂校验——只检查最基本的格式问题。
        深层语义问题（如 system prompt 放最后）只警告不报错。
        """
        if not isinstance(messages, list):
            raise ValueError(f"messages 必须是 list，不能是 {type(messages).__name__}")

        if len(messages) == 0:
            raise ValueError("messages 不能为空——至少需要一条 user 消息")

        for i, msg in enumerate(messages):
            if not isinstance(msg, dict):
                raise ValueError(
                    f"messages[{i}] 必须是 dict，不能是 {type(msg).__name__}。\n"
                    f"正确格式: {{\"role\": \"user\", \"content\": \"问题\"}}"
                )

            if "role" not in msg:
                raise ValueError(
                    f"messages[{i}] 缺少 'role' 字段。\n"
                    f"当前内容: {msg}"
                )

            if "content" not in msg:
                raise ValueError(
                    f"messages[{i}] 缺少 'content' 字段。\n"
                    f"当前内容: {msg}"
                )

            role = msg["role"]
            if role not in VALID_ROLES:
                raise ValueError(
                    f"messages[{i}] 的 role='{role}' 不合法。\n"
                    f"合法值: {', '.join(sorted(VALID_ROLES))}"
                )

    def _handle_error_status(self, response: httpx.Response) -> None:
        """根据 HTTP 状态码分类处理错误。

        每种状态码对应不同的用户操作建议——不让用户看到 401 后不知道该干什么。
        """
        if response.is_success:
            return  # 2xx，正常

        status = response.status_code
        # 尝试从响应体获取服务端给出的错误信息
        error_detail = self._extract_error_detail(response)

        if status == 401:
            raise AuthenticationError(
                f"认证失败（401）：API Key 无效或已过期。\n"
                f"当前 Base URL: {self._base_url}\n"
                f"当前 API Key 前缀: {self._api_key[:8]}****\n"
                f"检查: 1) .env 中 LLM_API_KEY 是否正确 2) Key 是否已过期\n"
                f"服务端信息: {error_detail}"
            )
        elif status == 403:
            raise AuthenticationError(
                f"访问被拒绝（403）：API Key 无权访问该资源。\n"
                f"可能原因: 账户未激活、区域限制、权限不足\n"
                f"服务端信息: {error_detail}"
            )
        elif status == 429:
            raise RateLimitError(
                f"速率限制（429）：请求太频繁或 Token 额度用完。\n"
                f"建议: 等 3-5 秒后重试；如果持续出现，检查账户余额和额度\n"
                f"服务端信息: {error_detail}"
            )
        elif status == 404:
            raise ModelError(
                f"端点或模型不存在（404）。\n"
                f"当前 Base URL: {self._base_url}\n"
                f"当前 Model: {self._model}\n"
                f"检查: LLM_BASE_URL 和 LLM_MODEL 是否正确\n"
                f"服务端信息: {error_detail}"
            )
        elif 400 <= status < 500:
            raise LLMError(
                f"请求参数错误（{status}）：请求体格式或参数值不正确。\n"
                f"服务端信息: {error_detail}"
            )
        elif status >= 500:
            raise LLMError(
                f"LLM 服务端错误（{status}）：服务器内部问题，和你的请求无关。\n"
                f"建议: 等 10 秒后重试；如果持续出现，检查服务商状态页\n"
                f"服务端信息: {error_detail}"
            )
        else:
            raise LLMError(f"未知 HTTP 错误（{status}）: {error_detail}")

    def _extract_error_detail(self, response: httpx.Response) -> str:
        """从错误响应体中提取服务端给出的错误描述。

        不是所有 LLM 服务商都返回标准的 error.message 格式，
        解析不到也不报错——返回原始文本即可。
        """
        try:
            body = response.json()
            # OpenAI-compatible 的错误格式: {"error": {"message": "...", "type": "..."}}
            if isinstance(body, dict) and "error" in body:
                error = body["error"]
                if isinstance(error, dict):
                    msg = error.get("message", "")
                    t = error.get("type", "")
                    return f"{t}: {msg}" if t else msg
                return str(error)
            return response.text[:300]  # 截断，防止返回整页 HTML
        except Exception:
            return response.text[:300]

    def _parse_response(self, response: httpx.Response) -> str:
        """从成功响应中提取模型回答内容。

        同时检查 finish_reason——如果是 'length'，说明回答被截断了，
        要在返回内容末尾加警告，避免用户把不完整的回答当完整结果。
        """
        try:
            body = response.json()
        except Exception as e:
            raise LLMError(
                f"LLM API 返回的不是有效 JSON。\n"
                f"原始响应前 200 字符: {response.text[:200]}"
            ) from e

        # 检查 choices 数组
        choices = body.get("choices")
        if not choices or not isinstance(choices, list):
            raise LLMError(
                f"LLM 响应中缺少 'choices' 字段或格式不对。\n"
                f"响应体: {body}"
            )

        first_choice = choices[0]
        message = first_choice.get("message")
        if not message or not isinstance(message, dict):
            raise LLMError(
                f"LLM 响应中缺少 'choices[0].message' 字段。\n"
                f"响应体: {body}"
            )

        content: str = message.get("content", "")
        finish_reason: str = first_choice.get("finish_reason", "unknown")

        # ---- finish_reason 检查 ----
        if finish_reason == "length":
            # 回答被截断了——在末尾加警告
            warning = (
                f"\n\n⚠️ [警告] 输出被截断（finish_reason=length）。"
                f"当前 max_tokens 不足以容纳完整回答。"
                f"建议增大 max_tokens 参数后重试。"
            )
            content += warning
        elif finish_reason == "content_filter":
            raise ContentFilterError(
                f"输出被内容安全策略拦截（finish_reason=content_filter）。\n"
                f"你的输入或模型的输出触发了安全过滤。\n"
                f"建议: 检查提示词中是否有敏感内容"
            )

        # ---- Token 用量信息（可选的调试信息） ----
        usage = body.get("usage", {})
        if usage:
            prompt_tokens = usage.get("prompt_tokens", 0)
            completion_tokens = usage.get("completion_tokens", 0)
            total_tokens = usage.get("total_tokens", 0)
            # 成本信息可以帮助你建立"每次调用花了多少钱"的直觉
            # 在终端打印但不在返回值里加——返回值应该是纯回答文本
            # （Day 5 会在 CLI 里通过 Rich 展示这些信息）

        return content

"""

运行方式：

"""

from app.config import get_config, ConfigError
from app.llm_client import LLMClient, LLMError


def demo_multi_turn() -> None:
    """演示多轮对话：验证 history 是否生效。"""
    print("=" * 60)
    print("  多轮对话演示 — 验证上下文保持能力")
    print("=" * 60)

    # 加载配置
    try:
        cfg = get_config()
    except ConfigError as e:
        print(f"配置错误: {e}")
        return

    # 初始化 messages——第一轮只有 system + user
    messages: list[dict[str, str]] = [
        {
            "role": "system",
            "content": (
                "你是一个 Python 后端导师，语气专业但友好。"

                "每次回答先给出结论，再给代码示例，最后提醒一个常见错误。"
            ),
        },
        {"role": "user", "content": "Python 的 @dataclass 装饰器有什么用？"},
    ]

    with LLMClient(cfg) as client:
        # ---- 第一轮 ----
        print("\n💬 第一轮对话")

            messages.append({"role": "assistant", "content": answer1})

            print(f"   ❌ 第一轮失败: {e}")
            return

        # ---- 第二轮：追问（依赖第一轮上下文） ----

            "role": "user",

        except LLMError as e:
            print(f"   ❌ 第二轮失败: {e}")
            return

    # ---- 打印完整对话历史 ----
    print(f"\n{'=' * 60}")
    print(f"  完整对话历史（共 {len(messages)} 条消息）")

    for i, msg in enumerate(messages):

        content_preview = msg["content"][:80]
        icon = {"system": "⚙️", "user": "👤", "assistant": "🤖"}.get(role, "❓")
        print(f"  {icon} [{i}] {role}: {content_preview}...")

    print(f"\n  ✅ 多轮对话演示完成")
